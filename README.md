# Naive BASIC bas2apk 1.0

**BASIC → standalone Android APK, directly on Android.**

Naive BASIC bas2apk turns a `.bas` program into an independent Android application. It uses the included **NaiveWORK 0.2G** runtime/template, replaces its BASIC program, prepares a separate application name and package id, then signs the resulting APK using the historical V1/JAR scheme required for compatibility with old Android versions.

The project is intended to remain usable on old hardware alongside **Naive BASIC** itself.

## Ready BASIC programs

**[Examples-BAS — games, music and tests](https://github.com/ma-beast/Examples-BAS)**

The same `.bas` files can be run directly in Naive BASIC 1.0 or used here as source programs for building standalone APKs.

## How bas2apk 1.0 works

1. The file browser starts at `Environment.getExternalStorageDirectory()`.
2. Select a `.bas` file.
3. **NaiveWORK 0.2G** (`app/src/main/assets/NaiveWORK_0.2G.apk`) is used as the APK template.
4. `assets/programs/program.bas` inside the template is replaced with the selected BASIC program.
5. The installed application name is derived from the `.bas` filename.
6. A separate package id `com.naivework.<name>` is generated for each program.
7. The resulting APK is signed with the included NaiveWORK Export key using the historical V1/JAR signature scheme.
8. The APK is saved next to the source `.bas` with the same base filename.

## NaiveWORK 0.2G

`NaiveWORK-template/` contains the source project of the runtime/template used for generated applications.

NaiveWORK 0.2G is based on the **Naive BASIC 0.9.3G-BETA interpreter**. It includes support used by the release template, including background `PLAY!` and numeric `PLAY`, so programs using these features work in generated standalone APKs.

The ready template APK used by bas2apk is stored at `app/src/main/assets/NaiveWORK_0.2G.apk`.

## bas2apk 1.0 label handling

NaiveWORK 0.2G uses `android:label` through a resource instead of a literal string stored directly in binary `AndroidManifest.xml`. Older bas2apk code searched for the literal `Naive WORK` string and therefore could not correctly prepare the newer template.

In 1.0, `BinaryXmlLabel` handles both forms. For the newer resource-based NaiveWORK template it adds the program name to the binary XML string pool and points `<application android:label>` to that string. The package id is changed separately as before.

## Public export signing key

The files `app/src/main/assets/export_private.pk8` and `app/src/main/assets/export_cert.der` are **intentionally included as part of bas2apk**. They form the common **NaiveWORK Export** signing pair used to sign APKs generated by the program. Without this pair, bas2apk cannot produce installable signed APKs autonomously.

This is a public template/export key, **not the author's personal Android developer/release key**. A signature made with this common key should therefore not be treated as proof of the identity or trustworthiness of a generated application.

## Source tree

- `app/` — Naive BASIC bas2apk 1.0 source and bundled runtime/signing assets.
- `NaiveWORK-template/` — complete source project for the NaiveWORK 0.2G template.
- `CHANGELOG_*.txt` — development history retained with the source.
- `CHANGELOG_1.0.txt` — changes in the final 1.0 release.

- **[Examples-BAS](https://github.com/ma-beast/Examples-BAS)** — games, music, tests and demonstration `.bas` programs.

# Naive BASIC bas2apk 1.0 — Русский

**BASIC → самостоятельный Android APK непосредственно на Android.**

Naive BASIC bas2apk превращает программу `.bas` в самостоятельное Android-приложение. Он использует встроенный runtime/template **NaiveWORK 0.2G**, заменяет находящуюся в нём BASIC-программу, задаёт отдельные имя приложения и package id, а затем подписывает готовый APK исторической схемой V1/JAR, необходимой для совместимости со старыми версиями Android.

Проект рассчитан на работу в том числе на старом железе рядом с самим **Naive BASIC**.

## Готовые BASIC-программы

**[Examples-BAS — игры, музыка и тесты](https://github.com/ma-beast/Examples-BAS)**

Те же `.bas` можно запускать непосредственно в Naive BASIC 1.0 либо использовать как готовые исходники для создания самостоятельных APK через bas2apk.

## Как работает bas2apk 1.0

1. Файловый браузер открывается с `Environment.getExternalStorageDirectory()`.
2. Пользователь выбирает `.bas`.
3. В качестве шаблона используется **NaiveWORK 0.2G** (`app/src/main/assets/NaiveWORK_0.2G.apk`).
4. `assets/programs/program.bas` внутри шаблона заменяется выбранной BASIC-программой.
5. Имя установленного приложения берётся из имени `.bas`.
6. Для каждой программы создаётся отдельный package id `com.naivework.<имя>`.
7. APK подписывается встроенным ключом NaiveWORK Export по исторической схеме V1/JAR.
8. Готовый APK сохраняется рядом с исходным `.bas` под тем же базовым именем.

## NaiveWORK 0.2G

`NaiveWORK-template/` содержит полный исходный проект runtime/template, используемого создаваемыми приложениями.

NaiveWORK 0.2G основан на интерпретаторе **Naive BASIC 0.9.3G-BETA**. В релизном шаблоне поддерживаются в том числе фоновый `PLAY!` и числовой `PLAY`, поэтому использующие их программы работают и в созданных автономных APK.

Готовый APK-шаблон bas2apk находится в `app/src/main/assets/NaiveWORK_0.2G.apk`.

## Обработка android:label в bas2apk 1.0

NaiveWORK 0.2G задаёт `android:label` через ресурс, а не буквальной строкой непосредственно в бинарном `AndroidManifest.xml`. Старый код bas2apk искал строку `Naive WORK` и поэтому не мог правильно подготовить новый шаблон.

В версии 1.0 `BinaryXmlLabel` обрабатывает оба варианта. Для нового ресурсного шаблона NaiveWORK имя программы добавляется в строковый пул бинарного XML, после чего `<application android:label>` указывает на эту строку. Package id изменяется отдельно, как и раньше.

## Публичный экспортный ключ

Файлы `app/src/main/assets/export_private.pk8` и `app/src/main/assets/export_cert.der` **намеренно входят в состав bas2apk**. Это общая пара **NaiveWORK Export**, которой подписываются создаваемые программой APK. Без неё bas2apk не смог бы автономно создавать устанавливаемые подписанные APK.

Это публичный ключ шаблона/экспорта, **а не личный Android developer/release-ключ автора**. Поэтому подпись этой общей парой сама по себе не подтверждает авторство или доверенность созданного приложения.
